# Contributing to Jet Plane

Thanks for your interest in contributing! Please follow these guidelines so we can review and accept contributions smoothly.

## How to file an issue
- Search existing issues first to avoid duplicates.
- Use clear titles and include steps to reproduce, expected vs actual behavior, and relevant environment details (macOS version, Jet Plane version).

## Pull requests
- Fork the repo and create a branch named like `fix/short-description` or `feat/short-description`.
- Open a PR against the `main` branch with a descriptive title and summary.
- Keep changes focused and small; one feature/bugfix per PR.
- Link related issues with `Fixes #<issue-number>` when appropriate.

## Code style & tests
- Follow the existing code style. If new files include tests, add them and ensure they pass.
- Include documentation updates (README, usage examples) when behavior or APIs change.

## Review process
- PRs will be reviewed and may request changes. Be responsive to feedback.
- We run automated checks where configured; fix any failing checks before merging.

## Commit message format
- Use short, descriptive commit messages. Example: `fix(uninstaller): require admin when removing /Library files`

## Security & sensitive data
- Don't include secrets, credentials, or exploit code in issues or PRs. For security reports, see SECURITY.md.

## Code of Conduct
- By contributing you agree to follow the project's Code of Conduct. If you want, we can add a CODE_OF_CONDUCT.md to the repo.

Thank you — we appreciate your help!
